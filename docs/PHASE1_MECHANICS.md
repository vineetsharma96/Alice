# Phase 1 implemented mechanics and contracts

This document supersedes Phase 0 proposals where explicitly stated below. The long-term design is preserved. Phase 2 bodies/needs, model cognition, chemistry, teaching, a viewer and experiment branches remain unimplemented.

## Native authority

`core/world.cpp` is the single source of physical truth. `World.step(n)` executes all fixed ticks, bounded to 10,000 per batch, without Python callbacks; pybind11 releases the GIL during stepping and returns a batch of events. `snapshot`, `observe_batch` and `checkpoint` do not advance time. Python does not implement movement, spatial lookup or material transfer rules. The original `underworld_core` executable remains a Phase 0 initialization compatibility probe; the actual Phase 1 kernel is `underworld_sim` and `_underworld`.

The region has hard rectangular boundaries and one solid circular rock at its centre (radius 1 m). Actors are circles, radius 0.25 m, moving at at most 1 m/s. Resource piles are passable points with explicit masses. Stable IDs are unique within a run and never recycled. The allocator counter is saved even though dynamic entity creation is deferred. Agent 1 is placed at (2,3) m so transfer tests have reachable food. Other agents are seeded rejection-sampled without overlap; the Phase 0 scene coordinates remain archived and are not a migration format.

The spatial index is a 4 m uniform grid. Range queries inspect intersecting cells then check Euclidean distance and sort entity IDs. Movement tests the whole proposed segment against neighbouring expanded solid circles, preventing tunneling at the allowed steps. An obstructed move fails with `COLLISION` rather than sliding. Actors advance in sorted ID order and rebuild the grid after each successful move. This is an authored sequential collision reservation rule, not an impulse, momentum or friction solver. Unreachable endpoints fail after their requested duration; no pathfinding is implemented. Bounds require the entire circle to fit. Parameters and timestep limits are validated by C++.

## Time, energy and authored actors

Tick is uint64; simulated seconds are `tick * dt_s`, with default dt=0.1 s. Wall-clock time never drives physical updates. Inspecting, saving or stopping the process does not advance the world; offline catch-up does not occur.

With scripted mode enabled, an authored test controller draws deterministic movement destinations using the world RNG at every configured interval (50 ticks by default) for idle actors. They request 5 simulated seconds of movement. RNG state and next decision tick survive checkpoints. Busy actors are skipped; no survival, goals, language, utility policy or intelligence is claimed. `new --manual` disables these actors and allows only explicit recorded action requests.

An explicit daylight boundary source has period 86,400 s and flux `100 * max(0,sin(2*pi*t/86400))` W/m². `t=0` is dawn; noon is 21,600 s. Each tick adds `flux * world_area * dt` joules using a left-endpoint fixed-step integral to an abstract environmental reservoir. No mass is produced, no sinks/conversions exist, and both cumulative input and reservoir have the same value. This is an authored energy source, not a thermal or climate model. The day/night test takes every 1 s physical step from dawn through noon and into night, and verifies zero input during night. Thermodynamic validity and reactions remain Phase 5.

## ActionRequest implementation of v1

The native binding requires exactly these fields: `schema_version`, `run_id`, `request_id`, `agent_id`, `observation_version`, `action_type`, `target_ids`, `parameters`, `requested_duration`. This last spelling follows the supplied Foundation Prompt; it supersedes Phase 0's proposed `requested_duration_s`. Values are seconds. Duration [0.1,60] is rounded up to whole physical ticks. Strings for counters are canonical uint64 decimal strings; IDs follow the existing opaque-ID rules. The binding enforces the supplied run ID and explicit `principal_agent` against the request. The CLI is a trusted operator and routes each request as its stated agent; later cognition must supply its scheduler-assigned principal, never infer it from model text.

- `move`: no target IDs, parameters exactly `x_m`, `y_m`; finite destination inside circle-adjusted bounds. Progresses at 1 m/s, completes on arrival, otherwise fails `COLLISION` or `DURATION_EXPIRED`.
- `gather`: one resource target, parameter exactly `mass_kg`; moves mass from the pile to the requester's inventory after the action duration.
- `deposit`: explicit Phase 1 extension for the inverse inventory transfer; same target/parameter rules. Allows conservation and negative-inventory testing without adding consumption/bodies from Phase 2. Deposits return material only to a pile of that material; no arbitrary material creation.

Mass resolution is one microgram (`1 kg = 1,000,000,000 ug`); native state uses signed int64 micrograms. Per-action mass is (0,10] kg and must be representable at that resolution. Totals must remain exactly food=16 kg, water=64 kg, inert material=32 kg. There are no sources or sinks after initialization. Transfers check visible resource type, 8 m range, 1.5 m reach and availability on acceptance, then reach and availability again on completion. Competing requests cannot overdraw: execution is ordered, so one can fail after another consumes the available material. An actor can have at most one pending action. No other actor's inventory can be used as a source or target. Checkpoint/transaction boundaries enforce invariants before commit.

Duplicate `(agent_id, request_id)` with identical native action content returns the persisted original/current result, including after restart. Conflicting content is rejected. Malformed schema/authorization errors raise before native mutation. Logical rejections carry bounded error codes and are journaled; accepted is distinct from completed. Additions to Phase 0's proposed errors are `COLLISION`, `DURATION_EXPIRED` and `REQUEST_LIMIT`. Results currently carry status/error, request/agent/run IDs and start/completion/version counters; the observation carries later public consequences. Rich per-result `event_refs`/effect projections are deferred to the everyday-agency contract; Phase 1 provenance is the exact request-ID-linked event journal, not an invented result field.

The JSONL file boundary rejects duplicate keys, invalid UTF-8, nonfinite JSON, deep nesting, oversize payloads and unsupported field/type shapes. Each line is `{"at_tick":"0","request":{...}}`. All scheduled ticks must lie inside the current bounded advance call. Decisions at a tick are applied in file order before the scripted controller/physics update. Stale versions and fabricated targets cannot cause an action effect. Hidden or nonexistent resources share `TARGET_UNAVAILABLE`. Public getters expose no global state to a cognitive provider; no provider exists yet.

## Observations

`observe_batch([agent_ids])` returns each requested actor's own state, its recent action results and entities within 8 m. Other actors' inventories are removed. There are no private memories or bodies yet. This geometric mechanics projection is not Phase 2 human perception: occlusion, audibility, need/sense variation, full message quotas and speech are deferred. `snapshot()` is privileged operator inspection and includes all positions, inventories, pending actions, total masses, time and energy; it must not be used as model input. Storage attaches config/state hashes to snapshots.

## Checkpoint and persistence format

Core text checkpoints start `UW1 <build_id>` and serialize all authoritative fields, mt19937_64 engine state, tick/event/allocator counters, entities/inventories, outstanding actions including remaining duration, request deduplication/results, buffered events and scripted scheduler state. Double precision is round-tripped using 17 significant digits and the classic locale. Restore rejects version/build mismatch, truncation, excessive sizes, invalid counts, extra data and physical invariant violations, then rebuilds the derived grid. Checkpoints are internal trusted state, never accepted as an inhabitant action.

Python hashes the entire core serialization with SHA256. The native build ID hashes kernel/header/binding source, compiler ID/version and build type; Python's persistence/wire/config source is separately hashed and checked on resume. Run metadata records schema, config hash, seed via config, scripted flag, laws/package/build IDs, UTC creation and commit boundary. Run UUID and creation time are metadata outside the physical hash, allowing independent identical runs to compare physical state. Hash reproducibility is only promised on the same supported build/runtime; there is no cross-platform floating-point guarantee.

SQLite user_version=1 has one `run` head, bounded recent `events`, full external `decisions` and named `checkpoints`. Rollback journal DELETE, synchronous FULL, one writer. For each tick: lock with `BEGIN IMMEDIATE`; verify committed head/build/config; submit decisions to the staged native world; execute one tick; check native invariants; insert decisions and all tick events; prune old event rows; replace complete state/hash; `COMMIT`. Only after commit can observer reads see that tick. A failure rolls back the whole transaction and discards the staged object. Between ticks a competing writer is detected by head-hash comparison; its newer state is never overwritten. No model call occurs inside transactions.

An abrupt exit before commit recovers the previous head and matching journal; exit after commit retains the new tick. SQLite hot-journal recovery may need write access, so `resume` opens a writer transaction and verifies the head before optionally advancing. `inspect` is an actual query-only connection and never tries to repair a database. Power loss/storage hardware flush behavior has not been experimentally verified.

`save` stores a versioned named checkpoint in a transaction, then optionally uses SQLite's online backup API to a temporary sibling database, checks integrity, flushes it and publishes with an atomic no-overwrite hard link. The temp file is removed; a pre-existing destination is never overwritten. A failed backup can leave its named checkpoint committed; it does not partially advance simulation. The tested filesystem is Windows NTFS. Filesystems lacking hard links fail explicitly. Directory-entry durability under sudden power loss is not claimed. Resume a saved database at its committed head; restoring an old checkpoint into an existing run/rewriting its history is intentionally not offered. Future explicit experiment branching belongs to the intervention work.

Replay restores the initial checkpoint, uses the saved seed/RNG/scheduler and **recorded external requests** at their original ticks, verifies their recorded acceptance results, advances all ticks, and compares the final complete physical state hash. No model/network calls occur. Recent events can be pruned because the initial state and full decision journal remain; replay reconstructs them. Checkpoints are snapshots of complete state; a viewer snapshot alone cannot restore a run.

## Phase 1 limits

Population guard 64 (baseline 8; no scaling claims), maximum advance call 100,000 ticks, maximum run head 1,000,000 ticks, native batch 10,000, event retention default 10,000, at most 16 named checkpoints including initial, at most 10,000 external decision records and 10,000 native deduplication records (scripted and external combined). Reaching native dedup capacity rejects subsequent new action requests with `REQUEST_LIMIT`; authored movement may stop. These limits bound the prototype, not an unattended-operation implementation. Do not use it as a long-running autonomous world until Phase 7 quotas/retention/backpressure are implemented. No model, GPU, UI, needs, eating or chemical reactions are present.
