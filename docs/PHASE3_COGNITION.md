# Phase 3: identity, memory and bounded local cognition

The C++ UW2 laws remain unchanged. Python/SQLite schema 3 adds seeded identities, separate episodes, observed relationships, one-step plans and a private cognition journal. This is an approximation of agency. Memory accumulation does not modify model weights or establish human equivalence.

## Decision boundary and actions

`config/survival.toml` remains the default model-off world. `config/cognition.toml` enables an authored deterministic cognition provider; `config/local-model.toml` enables the measured local CPU adapter. Both keep utility survival. At each configured cognition interval one inhabitant is selected round-robin; busy/dead inhabitants are skipped. The configured daily call budget is shared across the population, counted by `floor(tick * dt / 86400)`, not per inhabitant. Calls may exhaust the budget early in a day; there is no pacing or background inference queue. The example interval is 250 ticks (50 simulated seconds), daily quota 96. The experiment deliberately uses quota 3 to prove exhaustion in a short run.

Inference pauses logical advancement for the entire population. A separate killable process provides a total deadline including process startup; the HTTP adapter also shares a monotonic deadline across server inspection, tokenization and completion. No SQLite writer lock is held during inference. Slow inference costs wall-clock time, not hunger/thirst ticks for a particular inhabitant. The observer's serialized controls/polling can wait at this boundary. This is an intentional logical pause, not a real-time asynchronous simulation.

One in-process inference lock rejects concurrent calls; the pinned server uses one parallel decoding slot. Independent coordinator processes are unsupported for inference scheduling. A durable attempt reservation consumes quota before inference starts. Interruption leaves an `interrupted_or_in_progress` journal record, no unearned action, and the utility policy can continue after restart. Completion commits only if physical and mental checksums still match its input. An external writer invalidates stale inference. There are no retries; timeout/provider failure/malformed JSON/invalid references invoke the authored baseline immediately. Daily quota or busy/dead skips perform no model call; routine utility remains available.

A plan has exactly `intent`, `target`, `text`, `interpretation`, `evidence`. Allowed intents: eat, drink, rest, inspect, speak. A compiler creates one native request with its own run/version/agent/request identifiers. Eat/drink amounts are fixed at .2/.3 kg; rest lasts 5 s; inspection .2 s; speech 1 s. Movement and gathering remain cheap utility actions. Text is limited to 160 UTF-8 bytes for speech and 240 for interpretation. References must belong to the retrieved episodes of that inhabitant. Inspect targets must be currently visible. The server grammar constrains vocabulary/references; an independent Python compiler and the native kernel still validate all results. A valid JSON plan can fail physically for insufficient supplies; failure is recorded rather than converted into a fact.

Pending plans are consumed once on the next physical tick. Dead/busy actors, expired plans (100 ticks), or urgent needs (hunger/thirst >= .5, fatigue >= .55) preempt cognition so utility survival has priority. Plans are recompiled against fresh permitted perception before submission. Physical decisions enter the existing journal with source `cognition`. Native result/event references retain their actual sequence IDs.

## Memory and privacy

Identities use a SHA-256-derived seed trait, an authored name and motivations. The baseline uses the motivation to choose inspection or local sharing when it has no carried food/water. These traits are prompt conditioning, not learned personalities. Each table keys private records by inhabitant. Providers receive a projected context containing only that inhabitant's own body/inventory, at most eight visible public IDs/kinds, up to three of its retrieved episodes and three observed relationships. Providers receive no DB/world handle, operator snapshot, hidden coordinates, other bodies or other private memories.

Completed/failed/rejected own action receipts become original episodes with receipt event references. Delivered speech becomes an `unverified_report` retaining speaker and delivery/event provenance. A relationship is only an observed hearing count plus its last 16 delivery references; hearing does not establish trust or agreement. Each thought records its permitted perception and a separate `derived_belief` labelled unverified, with own episode references and the perception source. Model interpretations never alter engine facts. No automatic summary replaces an original. There is no embedding model, weight training, global memory search, autonomous book reading or operator teaching in this phase.

SQLite retrieves at most the latest 64 episodes for one parameter-bound agent, ranks lexical term matches then recency in Python, and returns 1–8 records (default 3). An index supports the bounded per-agent window. Older episodes remain preserved but outside the retrieval window; this is an explicit limitation, not proof of perfect lifelong recall. Queries are at most 256 characters. Full stores stop at 10,000 original/derived episodes globally rather than deleting evidence. Cognition stops at 1,024 attempts per run as well as the daily quota. Existing physical limits remain. These bounds limit growth but are not a Phase 7 disk-rotation system.

## Persistence and reproducibility

`identities`, `episodes`, `relationships`, `plans`, `cognition_calls` have a canonical SHA-256 checksum in `cognitive_head`. Each physical tick atomically records its new episodes/plan state alongside the core and utility route state. Failure before commit rolls these back. Attempts are separate durable mental transactions with a reservation before inference and completion after it. Save/backup preserves all tables; restart verifies both physical/runtime and cognitive integrity.

Physical replay submits recorded cognition/utility/external requests without contacting a provider. It verifies the physical/utility head, while the stored mental tables are checksum-validated. It does **not** regenerate stochastic text, semantically replay mental history, or claim model bitwise determinism. Cognitive and physical hashes are distinct; private prompt/latency metadata is not part of the physical replay hash. Named checkpoints still describe UW2 core state; the standalone SQLite backup contains the full mental state at its head.

Private `cognition_calls.payload` stores context, original output, selected/fallback plan, error, limits, prompt, pinned model/server settings and measured latency. Timeout records retain context and runtime fingerprints so the prompt can be reconstructed even when the terminated worker never returned it. These DBs live in ignored `data/`; public evidence removes full prompts/context. No credentials, API headers, environment dumps or secrets are included. This is logical per-agent isolation within a trusted local operator application, not OS-level isolation from a hostile user who can open the database.

Schema 3 and the changed Python orchestration fingerprint deliberately reject Phase 1/2 saved runs. Old data files and phase reports remain preserved; no automatic migration is claimed. The native UW2 checkpoint/build and physical laws are unchanged.

## Local model and bounds

Official release `llama.cpp b11721`, commit `ff5a23376725e5a889fa0bfb987b7541dc304da0`, Windows CPU asset. Official publisher model `HuggingFaceTB/SmolLM2-360M-Instruct-GGUF`, revision `593b5a2e04c8f3e4ee880263f93e0bd2901ad47f`, Q8_0, 386,404,992 bytes. Exact SHA-256 pins are in `artifacts/phase3_model_pins.json`; downloads are local/ignored. `scripts/local-model.ps1` verifies downloads and optionally starts a hidden loopback server. No inference framework was installed into Python.

The adapter checks the server build and expected model filename, uses the model's ChatML prompt, and calls `/props`, `/tokenize`, `/completion` with schema-constrained output. The setup script checks actual weight/archive hashes; filename checking alone is not cryptographic server attestation. Only literal HTTP loopback origins are accepted, proxies and redirects are disabled, and there are no remote API adapters. This restricts the adapter's network destinations; OS-enforced egress isolation of the entire process is deferred to Phase 7.

Server: context 2,048 tokens, two CPU threads, one parallel slot, zero GPU layers and no web UI. Example client: at most 1,024 input tokens, 192 output tokens, 30 s total deadline, no retry, prompt <=4,096 bytes, raw output <=4,096 bytes and HTTP response <=256 KiB. Input plus reserved output must fit the measured context. Grammars do not guarantee meaningful reasoning. Conversations are single local utterances, with no unbounded conversational loop. The small model can parrot prompt phrases, supply weak interpretations, omit useful evidence, or choose actions without resources. Failures remain evidence and fallbacks are labelled.

See `STATUS.md` and `artifacts/phase3_local_model.json` for actual run metrics. PSAPI peak working set includes mapped pages and the server process lifetime (including warm-up/probes); worker and parent memory are reported separately. Their independent peaks must not be summed as a simultaneous machine peak. Zero GPU layers means no dedicated model VRAM allocation; Windows integrated graphics memory was not profiled. The short experiment measures a partial simulated day and records the actual day bucket/quota. It is not a 24-hour or long-term unattended benchmark.
