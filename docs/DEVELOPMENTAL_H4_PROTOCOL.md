# H4 prospective protocol: useful single location signals

Written before H4 development or measurement. Preserve all H0-H3 source pins,
native UW9/DB10, G worlds/negatives and the sealed failed Phase9 study. Models,
regeneration, new release labels and H5 sequences/UI are excluded.

Development seed 43. Confirmation seeds 9203, 9227, 9257, 9277, 9293, never used
for H4 tuning. Freeze implementation/tests/config/protocol before confirmation.
New four-person 32x32 cohorts only, from the unchanged native H3 initializer.
Two spatial cells and a hub are authored finite-landmark scaffolding, not a
learned general coordinate language. Policy navigation coordinates must come
from each person's actual previous visits. No shared symbol dictionary.

Training has two separate tasks. First, two native H2 deposit/speech examples
each for food and water identify resource classes. Second, each receiver visits
two distant landmarks, hears three private coined location tokens at each site,
and associates them with its own perceived position. Only current native speech
from a visible, nearby speaker in the same spatial cell can ground a location.
Location tokens must not overlap that speaker's resource tokens. Learning one
does not grant the other. No object/location token sequence or word order.
Finite private limits: two visited landmarks, two location productions and two
partner-channel location meanings, eight need-outcome entries, sixteen source
memories; existing 2048 evidence records/person and native quotas still apply.

Each receiver also gathers and consumes actual food/water twice, storing its
own measured changes in hunger/thirst, native action and resource percept.
The need scheduler uses those predictions and current body needs; needs >=.45
and predicted positive relief can select a goal. Without adequate predictions,
bounded inspection/information inquiry is an explicitly engineered preference.
Navigation, gather/consume prerequisite logic and any emergency override are
authored and counted. Task assignment is never credited as autonomous goals.

Primary cooperation is explicitly an assigned water acquisition task. A scripted
scout visits one remembered landmark, physically observes accessible new water,
returns to hearing range and emits one location token. The receiver cannot see
the resource from the hub. Two scenarios/seed, one at each landmark, each using
a labelled backup of the same trained life. Exactly one new .05kg water source
is introduced per scenario as an accounted operator boundary input; no resources
are silently replenished or bodies reset. Other landmarks have no training stock.
Base-world water remains available at the hub; the assigned task is remote-source
acquisition, not proof that communication is necessary for survival. The need
policy may legitimately use nearby supplies without asking the scout.
Four matched branches/scenario: enabled, muted (native rest), scrambled (the
other privately coined site token), identity-only (the learned water word).
All branches start at the same native head after the same scout movement.

Receiver gets its own observation/memory and actual heard token, never the scout's
private target ID/coordinates. Decoded unseen-source reports remain unverified.
It may attempt one remembered site; muted/unknown-location cases use a saved
private random tie break, counted as bounded curiosity fallback. Arrival requires
own perception and stock/reach revalidation, then native inspect, gather and
drink. Goal credit needs real acquired and ingested water from that source.
An identity word alone must not be interpreted as a location. Count native
acceptance/completion separately from actual acquisition/need relief.

Primary gate over ten feasible cases/arm: enabled >=.80, >=.20 above both muted
and scrambled; >=4/5 seeds improve over scrambled; identity-only never decodes
a location; acquisition and report-confirmation proofs are native; no unnecessary
rejections, hidden target arguments, vocabulary learning during scoring, models
or protective fallback in enabled cases. If muted chance results prevent the
effect threshold, retain a failed gate without tuning held-out seeds.

Additional separate checks: five depleted-after-sighting cases (enabled only),
where another real native actor removes stock; zero invalid gather attempts and
no false goal/report success. Scarcity is not a policy defect. A six-decision
need-policy window/seed and a matched frozen-prediction backup compare actual
self-selected goals, inspection/inquiry, source revisits, completed consumption,
need relief and prediction dependence. Require at least one own-need-selected,
native-completed goal/seed and changed choices under same-state prediction
ablation; otherwise report need-policy failure separately from communication.
No global independent-intelligence or autonomous scout/teaching claim follows.
An additional native regression connects an own-need goal to an actually heard
location report when no own accessible/remembered source resolves it. Inquiry
is an authored flag/rest/inspection affordance, not a learned request symbol.

Report five-seed counts/rates, descriptive intervals, native rejection reasons,
missed feasible first-site opportunities, scarcity, all living bodies/health,
scout and receiver travel/actions, inquiry/curiosity/fallback counts, learning
retention and simulated versus wall durations. Counterfactual branches are not
one lifetime. Verify native invariants/replay, fresh-process resume, source pins,
idempotent native-outcome/report updates and missing-source/archival refusal.
Progressive need windows (2 then 6 decisions in the same save) preserve bodies,
needs, memories, resources, RNG and pending requests. Any cap stops explicitly.
Caps: 96 navigation steps/action route; one site/assigned trial; 240 wall s/arm,
900/seed, 4500/study; 300s child limit. Revise transparently before confirmation
if development proves these budgets impractical. Failed attempts remain evidence.
